# 관리자 CMS 최소 구현 계획

작성일: 2026-07-30
상태: 1단계 UI 구현 완료, 다음 단계 승인 대기

1. 목표

관리자 화면에서 페이지, 섹션, Vlog, Contact를 안전하고 쉽게 관리한다. 처음부터 상용 CMS 수준의 자유 편집기를 만들지 않고, 현재 소개 사이트 운영에 필요한 기능만 먼저 안정적으로 제공한다.

2. 이번 범위

페이지 목록, 검색, 기본 편집, 게시, Soft Delete
Vlog 목록, 검색, 글 작성, 기본 텍스트 편집, 게시, Soft Delete
Contact 페이지 기본 편집
Contact 문의 목록 조회
섹션 순서 변경은 드래그앤드롭 대신 위로 이동, 아래로 이동 버튼으로 제공
섹션 복사는 기본 구조가 안정화된 뒤 추가
로그인 전 관리자 화면과 관리자 API를 모두 차단
자동 저장 초안과 명시적 Publish 분리

3. 이번에 보류하는 기능

디자인 요소를 임의 배치하는 자유 캔버스
폰트, 색상, 간격, 모션의 전체 관리자 편집 패널
실시간 3단 반응형 미리보기
동시 편집 충돌 감지
버전 복구 화면
감사 로그 전용 화면
드래그앤드롭 순서 변경

4. 단계별 진행

1단계: 로그인 게이트와 관리자 UI
Cloudflare Access 인증 화면, 좌측 고정 메뉴, 대시보드, 목록/편집 화면 골격을 만든다.
현재 완료: 로그인 게이트와 pages, Vlog, Contact, assets 화면 골격 구현.

2단계: 페이지와 Vlog 편집
기존 CMS 스키마에 맞춘 기본 텍스트, 요약, 본문, 섹션 목록 편집을 연결한다.
저장 전에는 초안으로만 유지하고, 저장 결과를 새 탭에서 확인할 수 있게 한다.

3단계: Contact 문의함과 최소 저장 API
문의 목록, 읽음 상태, 상세 확인을 제공한다. 관리자 인증을 통과한 요청만 읽기와 상태 변경을 허용한다.

4단계: Publish, Soft Delete, 권한
게시 전 검증, Soft Delete, 복구 가능 상태를 연결한다.
Publish 전역 Lease는 5분 TTL로 설정하고 갱신하지 않는다. 오류로 해제되지 않아도 5분 뒤 자동 만료되어 다음 게시가 인수할 수 있어야 한다. 게시 요청에는 Lease 소유 확인과 fencing token 검사를 둔다.

5단계: 보안 및 회귀 검증
인증 없는 관리자 페이지와 API 거부, 운영 빌드 확인, 페이지별 콘텐츠 회귀, 게시/삭제 회귀, 접근성 기본 점검을 수행한다.

12단계 도메인 연결 전 체크리스트
ADMIN_TEST_BYPASS가 운영 환경에서 비활성인지 확인한다.
운영 빌드에서 테스트 우회가 남아 있으면 실패하도록 확인한다.
Cloudflare Access 정책에서 허용 이메일 또는 그룹만 관리자 경로에 접근하는지 확인한다.
Publish Lease의 5분 TTL과 fencing token 검사를 확인한다.

5. 예상 리스크와 해결 방식

리스크: 기능 범위가 상용 CMS 수준으로 커짐
해결: 기본 콘텐츠 운영에 필요한 기능만 먼저 구현하고 보류 목록은 운영 데이터가 쌓인 뒤 재평가한다.

리스크: 인증 우회가 운영에 남는 백도어가 됨
해결: 로컬 테스트 플래그는 개발 환경에서만 허용하고 운영 환경에서는 예외를 발생시킨다. 도메인 연결 전에 플래그 비활성 검사를 필수화한다.

리스크: 게시 중 오류로 전역 Lease가 영구 점유됨
해결: 5분 TTL, 갱신 없음, 만료 후 자동 인수, fencing token 검사를 사용한다.

리스크: 사이트 구조 변경으로 관리자 편집기가 깨짐
해결: 페이지와 섹션을 위치가 아닌 안정적인 id와 schema version으로 연결하고, 모르는 블록은 삭제하지 않고 읽기 전용으로 표시한다.

리스크: 관리자에서 저장한 내용이 공개 화면과 다름
해결: Publish 전 초안 미리보기와 공개 페이지 새 탭 확인을 제공하고, 공개 라우트 회귀 테스트를 유지한다.
